Purpose

Log Integrity Checker is a self-contained tool for recording SHA-256 hash baselines of log files and directories, and detecting changes against those baselines. It detects modifications, missing files, and unexpected new files.

The tool provides two interfaces from a single Python file: a command-line interface for scripting and automation, and a local web interface for interactive use.

The tool does not send file contents or hashes anywhere. All processing happens locally. No data ever leaves the machine.

Architecture

Single-file design

The entire project lives in app.py. It contains the hashing engine, baseline store, CLI parser, HTTP server, and web UI (inlined HTML/CSS/JS) — all with zero third-party imports.

Baseline store

Baselines are stored as per-target JSON manifests in a platform-appropriate user state directory. Writes are atomic (write-to-temp then os.replace) and guarded by a file lock. Manifest files and the store directory are created with owner-only permissions on POSIX systems.

PlatformDefault store location
macOS~/Library/Application Support/log-integrity
Linux$XDG_STATE_HOME/log-integrity (fallback: ~/.local/state/log-integrity)
Windows%LOCALAPPDATA%\log-integrity

Features

Simple CLI usage

Pass a file or directory directly — no subcommand required. The tool auto-detects whether to initialise a baseline or run a check.

./app.py /var/log/syslog        # first run: creates baseline
./app.py /var/log/syslog        # second run: checks for changes
./app.py /var/log/syslog --json # machine-readable output

Web interface — file picker

The web interface (./app.py serve) presents a click-to-browse / drag-and-drop file zone as the primary input. No typing required — click the zone or drag a file onto it, then click Check integrity. The first upload stores the baseline automatically; every subsequent upload compares against it.

Directory support (advanced)

Server-side directory paths are supported via the Advanced section in the web UI and via CLI subcommands. All regular files under the directory are hashed recursively; symbolic links are skipped.

Hashing reliability

Large files are hashed in 1 MB streaming chunks (never fully loaded into memory). Files that change while being read are retried once and then reported as an error, preventing misleading hashes.
